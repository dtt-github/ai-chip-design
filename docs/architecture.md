# Architecture

## Overview

```
 browser ──────────────────────────────────────────────────────────────────────────────
  React app (apps/web)          Monaco editor + y-monaco      WebAssembly: wafer-sim, wafer-gds
  Design view · Blocks · Health  co-editing, language server   simulation, waveforms, layout
        │ HTTPS /api                 │ WebSockets                    (runs in Web Workers)
 ───────┼────────────────────────────┼──────────────────────────────────────────────────
  wafersmith-api (crates/wafer-api, axum)                                  OIDC provider
   ├─ auth (JWT from the OIDC provider's keys) ◄──────────────────────────── (Rauthy)
   ├─ projects, members, commits ──► wafer-git: one bare Git repository per project
   ├─ collab (yrs) ── shared working copy per project, saved to disk, reconciled with Git
   ├─ lsp ── one Verible language server per editor session, over a temporary copy
   ├─ spec / design (examples → testbenches) · blocks / chip (blocks → top level)
   ├─ gate ── in-process simulation (wafer-sim) that decides whether a change may merge
   ├─ agent, assistant ── Claude Messages API (tool loops), per-person AI budget
   ├─ ip, licence ── registry, pinned imports, licence compatibility
   └─ jobs ── Postgres queue + workers ──► wafer-jobs ──► docker run LibreLane (no network)
                                                    └─► gate-level simulation (Icarus)
        │                     │
     Postgres             data directory: repos/  collab/  jobs/<id>/
```

## Components

| Crate / app | Responsibility |
|---|---|
| `crates/wafer-api` | The only server process: HTTP and WebSocket API, background workers for flow runs and agent proposals, database migrations (`migrations/`). |
| `crates/wafer-git` | Bare Git repositories via libgit2: commits without a worktree, optimistic parents, path normalisation. |
| `crates/wafer-jobs` | The `Backend` trait for flow runs and its Docker implementation; LibreLane metrics and report parsing; safe reading of run outputs. |
| `crates/wafer-sim` | Event-driven Verilog simulator (pure Rust), checked line by line against Icarus Verilog (`tests/conformance`). Besides waveforms it records branch coverage and, for every value change, the assignment that made it (`origins`: line, text, the signals read and the `if`/`case` decisions around it), which the web app uses to explain values. |
| `crates/wafer-gds` | GDSII reader: parse, flatten hierarchy, tessellate for the GPU. |
| `crates/wafer-sim-wasm`, `crates/wafer-gds-wasm` | WebAssembly bindings used by the web app. |
| `apps/web` | React + TypeScript app (Vite): Design view, Code view (Monaco), runs, layout viewer, agent, IP. |

## Data and where it lives

| Data | Where | Notes |
|---|---|---|
| Users, projects, members, jobs, proposals, IP registry, AI usage | Postgres | Migrations in `crates/wafer-api/migrations`, run at start-up. |
| Project files and history | `data/repos/<project id>.git` | The source of truth for designs, specs (`spec.json`), chips (`blocks.json`), IP pins (`ip.lock.json`). |
| Shared working copy (uncommitted edits) | `data/collab/<project id>.ydoc` | One Yjs document per project. |
| Flow runs | `data/jobs/<job id>/` | `work/` (the flow's directory), `flow.log`, `gls/` and `gls-logs/`. Deleted after the retention period. |
| Sign-in (users, passwords, keys) | Rauthy's own database | Separate from Postgres. |

## Generated files

Some project files are generated from others, always by deterministic code (never by the AI), and
start with a `// Generated by Wafersmith` header. They are committed so that every tool sees
them, and regenerated whenever their source is saved:

| Source | Generated | Code |
|---|---|---|
| `spec.json` examples | `tb/examples/tb_ex_<id>.v` | `wafer-api/src/spec.rs` |
| `blocks.json` | `src/<chip>.v`, `src/wafer_adapters.v` | `wafer-api/src/blocks.rs` |

## How a change is accepted

Every testbench in the project (top-level modules named `tb*`, `*_tb` or `*test*`) must reach
`$finish`, print `PASS` and print nothing containing `FAIL`, `ERROR` or `MISMATCH`. The server
checks this itself (`gate.rs`) on the exact files that would be committed: for agent proposals
before merging, and again at merge time. After a flow run, the testbenches that drive the built
design run again on its gate-level netlist (`gls.rs`).

## Trust boundaries

- **People**: authenticated by the OIDC provider; roles per project decide what they can do.
- **Project content is untrusted**: it is simulated in-process only with bounded parsing, a large
  stack, step and size limits and a concurrency cap; it is synthesised only inside flow containers
  without network or capabilities. The server never follows symlinks a flow could have planted.
- **The AI is untrusted**: the agent works on a private copy, may only write Verilog and docs, and a
  person must merge; the assistant only returns data that the server checks and a person saves.
- **The host's Docker**: the API starts flow containers through it, which is the main accepted
  risk for the pilot; see [security-review.md](security-review.md).

## Design decisions

- **Rust on the server**: axum instead of FastAPI; Rauthy (Rust) instead of Keycloak.
- **Git**: bare repositories on disk via libgit2, behind `wafer-git`. A hosted forge (e.g. Forgejo) can
  come later; nothing in the API depends on one.
- **Flow runs**: local Docker containers behind the `wafer_jobs::Backend` trait; Kubernetes or a
  separate runner can be another backend. Job state lives in Postgres (no workflow engine yet).
- **Results** stay on local disk under `data/jobs/`, not object storage yet.
- **Simulator**: our own Rust simulator instead of a WebAssembly build of Icarus Verilog or
  Verilator (no trustworthy WebAssembly builds exist, and both depend on dynamic loading). It
  covers RTL and common testbench code, not all of Verilog; gate-level simulation uses Icarus in the
  flow container.
- **Layout viewer**: flattens the whole layout in the browser, fine up to a few million triangles;
  large SoCs will need tiling and instancing on the GPU.
- **Language server transport**: a Rust WebSocket bridge (`lsp.rs`) and a small client
  (`apps/web/src/lsp.ts`) instead of Monaco's bundled client, which can't be torn down between
  projects.
- **AI**: raw HTTP to the Claude Messages API (no official Rust SDK) with strict tool schemas;
  everything the model returns is checked by deterministic code before it matters.
